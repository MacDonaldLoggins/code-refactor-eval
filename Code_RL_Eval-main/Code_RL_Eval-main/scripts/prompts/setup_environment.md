## 任务步骤

### 1. 执行环境搭建命令（必须成功）
按顺序执行以下命令：

{setup_commands}

**如果遇到错误，你必须修复：**
- 仔细分析错误日志，定位根本原因
- 常见问题及解决方案：
  - 依赖冲突：调整版本约束，使用兼容版本
  - 缺失依赖：安装缺失的系统包或 Python 包
  - 网络问题：重试或使用镜像源
  - 权限问题：检查文件权限，必要时调整
  - 配置错误：修正配置文件中的明显错误
  - setuptools/build 工具问题：升级或降级构建工具
  - 版本探测失败：设置环境变量绕过（如 SETUPTOOLS_SCM_PRETEND_VERSION）
- 应用修复后，重新执行失败的命令
- 记录每次修复的内容和原因
- **不要放弃**：持续尝试不同的解决方案，直到成功

### 2. 运行测试套件验证环境（必须通过基本测试）
执行以下测试命令：

{test_commands}

**测试结果要求：**
- 核心功能测试必须通过（>80% 通过率）
- 如果有测试失败，分析原因：
  - 环境问题（缺依赖、配置错误）→ 必须修复
  - 需要外部服务（数据库、API）→ 可以接受，但需说明
  - 代码 bug（与环境无关）→ 可以接受，但需说明
- 如果失败率过高（>20%），说明环境未就绪，继续修复

### 3. 输出结果
最后，创建一个 JSON 文件 `/workspace/setup_result.json`，包含：
```json
{{
  "status": "success" | "partial" | "failed",
  "setup_commands_executed": [

    "修复 2：依赖冲突 package-a 1.0 vs 2.0 → 降级到 1.5 作为兼容版本"
  ],
  "test_results": {{
    "total": 100,
    "passed": 95,
    "failed": 5,
    "skipped": 0,
    "pass_rate": 0.95
  }},
  "final_status": "环境已就绪，95% 测试通过，5 个失败测试需要外部 Milvus 服务",
  "next_steps": "环境可用于重构任务"
}}
```

**状态定义：**
- `success`：所有 setup 命令成功，测试通过率 >= 80%
- `partial`：setup 成功但部分测试失败（已确认是合理原因）
- `failed`：setup 失败或测试通过率 < 80%（环境不可用）

## 约束
- 项目源码根目录是 `/workspace/repo`（当前工作目录即在此）；评测脚本位于 `/workspace`
- 可以修改配置文件（如 pyproject.toml、setup.py）来修复明显的构建问题
- 可以设置环境变量来绕过版本探测等问题
- 不要修改业务代码（src/、lib/ 等核心代码）
- 不要修改测试代码
- 如果某些测试失败但环境基本可用，标记为 "partial" 并详细说明原因
