# Behavior Contract

## Observers

- Twenty SDK app loader and metadata sync consumers that discover declarations by
  `universalIdentifier`, file exports, and logic-function registration.
- HTTP/app-route callers of partner self-service, marketplace, application
  intake, client-brief, TFT import, and opportunity matching logic functions.
- Workspace data consumers of partner, application, opportunity, partner-content,
  partner-link, partner-service, person, company, field, relation, view,
  view-field, navigation, page-layout, role, workflow, and script declarations.
- Partner-facing front components for My Profile and My Case Studies.
- Maintainers adding partner, opportunity, application, or shared functionality.

## Must preserve

- Every production UUID-like `universalIdentifier` and relation-field identifier
  string remains byte-identical; no schema declaration is dropped, duplicated, or
  re-registered under a new ID.
- Every `defineLogicFunction` public contract remains compatible: `name`,
  `universalIdentifier`, HTTP route `path`, `httpMethod`, `isAuthRequired`,
  `timeoutSeconds`, request payloads, response payloads, success semantics,
  failure reasons, and side effects.
- Partner self-service behavior remains compatible for reading profile data,
  saving profile fields, links, services and content, submitting content for
  review, resolving profile pictures, rendering markdown, and reconciling child
  records.
- Partner application intake behavior remains compatible for input validation,
  region and deployment-expertise derivation, company/person lookup or creation,
  partner creation/update, and Discord notification side effects.
- Opportunity intake and matching behavior remains compatible for TFT import,
  client-brief submission, opportunity deduplication, assignment propagation,
  won/lost outcome synchronization, and all GraphQL query/mutation semantics.
- Object, field, view, view-field, navigation-menu-item, page-layout, role,
  workflow, script, and application-config declarations continue to export the
  same metadata and are discoverable by the same app tooling.
- Existing unit tests continue to cover the same pure behaviors, and any moved
  integration tests keep their live-server requirements and setup semantics.
- Root `src/roles/**` and `src/scripts/**` files remain root-owned entrypoints;
  only minimal import-path updates required by the module split are allowed
  there.

## May change

- Private helper names, module paths, folder names below `src/modules/`, and
  implementation-only data structures.
- Test file location and test project configuration, as long as the same unit and
  integration boundaries remain selectable.
- Internal extraction into services, mappers, GraphQL operation modules,
  connector wrappers, utilities, and shared helpers.

## Out of scope

- Adding product features, changing partner workflow rules, changing permission
  or RLS behavior, changing copy/UI behavior, changing generated SDK packages, or
  modifying unrelated Twenty workspace packages.
- Replacing the live Twenty server required by integration tests or changing
  external service semantics such as Discord notification delivery.
- Moving `src/constants/universal-identifiers.ts`, root `src/skills/`, root
  `src/workflows/`, or relocating root `src/scripts/` and `src/roles/` away
  from their root-owned entrypoints.

## Unknowns

- Full live-server integration behavior depends on an external Twenty server and
  is not guaranteed by the default hard gates; Judge should treat passing unit,
  typecheck, UUID, and logic-function contract evidence as strong but not
  complete integration proof.
- `twenty-client-sdk` CoreSchema typings are normally generated by a live
  `yarn twenty dev` session, so the static evaluator uses baseline-relative
  source typecheck evidence rather than treating missing generated-schema types
  as a standalone failure mode.
- Performance of metadata sync and remote GraphQL operations is only indirectly
  observed unless a candidate adds or preserves focused integration evidence.

## Evidence map

| Claim | Primary evidence | Secondary evidence | Failure action |
|---|---|---|---|
| UUID and schema identity are preserved | `universal_identifier_preservation_pass` hard gate | diff inspection of object/field/view/page-layout files | hard gate fail |
| Logic-function public contracts are preserved | `logic_function_contract_pass` hard gate | unit tests and Judge inspection of handlers | hard gate fail |
| Unit-level behavior remains compatible | `partners_unit_tests` hard gate | focused tests moved into domain modules | hard gate fail |
| Module layout addresses the change-cost problem | `partners_module_layout_pass` hard gate | `module_layout_completion` objective metric and Judge inspection | hard gate fail or rubric loss |
| Build/type/import contracts are coherent | `partners_typecheck` and `partners_lint` hard gates | `logic_entrypoint_thinness` and `graphql_locality` objective metrics | hard gate fail or rubric loss |
